# GH-001 — Branch Protection Review Control

## Purpose
GH-001 is a security control designed to ensure that code changes undergo proper peer review before being merged into protected branches (e.g., `main`). This prevents unverified or potentially malicious code from entering the production codebase.

## Control Objective
To mathematically and deterministically evaluate if a branch protection policy enforces adequate review thresholds and dismisses stale approvals when new code is pushed.

## Evidence Model
The evidence is represented as an immutable model (`@dataclass(frozen=True)`). This guarantees that once evidence is collected or instantiated, it cannot be tampered with during the evaluation process, providing an auditable trail.

## Required Evidence
The `GH001Evidence` model requires the following fields extracted from the source (e.g., GitHub):
- `required_review_approvals` (Optional[int]): The minimum number of approvals required for a PR.
- `dismiss_stale_reviews` (Optional[bool]): Whether previous approvals are automatically dismissed when new commits are pushed.

## Evaluation Rules
The evaluation is executed by `evaluate_gh001()`, returning a strictly typed `EvaluationStatus`.

### PASS
The control passes if and only if:
- `required_review_approvals >= 2`
- AND `dismiss_stale_reviews == True`

### FAIL
The control fails if the evidence is present and complete, but one or more of the required conditions are not met (e.g., approvals are less than 2, or stale reviews are not dismissed). 

### UNKNOWN
`UNKNOWN` is fundamentally different from `FAIL`. It indicates that the evidence is completely missing (`None`) or lacks the required fields to make a deterministic decision. This prevents false negatives or false positives due to network errors, missing configurations, or unreadable data.

## Deterministic Evaluation
The `evaluate_gh001()` function is a pure, deterministic engine. It does not rely on external services, LLMs, or random variables. Identical evidence will always produce an identical result, making it 100% reproducible and testable.

## Limitations
- The current evaluator operates on data provided to it in memory. It does not yet automatically fetch real data from GitHub.
- The evaluation logic is hardcoded for GH-001 and is not yet part of a generic rule engine.
