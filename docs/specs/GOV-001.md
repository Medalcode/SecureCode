## 1. Problema y Contexto

SecureCode es una plataforma GRC (Governance, Risk, and Compliance) diseñada para automatizar la evaluación de controles de seguridad en repositorios GitHub (controles GH-001, GH-002 y GH-003).

A pesar de contar con una suite de pruebas rigurosa (216 pruebas aprobadas, cobertura de 90,03 % y pipelines automatizados de CI y Docker Smoke Test), se constató mediante la API de GitHub que la rama principal `main` carece de mecanismos de protección activos (`"protected": false`).

### Riesgos Identificados
1. **Push directo no verificado:** Cualquier colaborador con permisos de escritura puede realizar `git push origin main` directamente, eludiendo la ejecución previa de pruebas de regresión, análisis estático y pruebas en contenedor.
2. **Reescritura de historial (Force Push):** La rama principal está desprotegida ante comandos `git push --force`, lo que puede alterar la trazabilidad forense de commits validados o destruir historial de versiones.
3. **Eliminación accidental:** La rama `main` puede ser eliminada remotamente mediante `git push origin --delete main`.
4. **Desconexión con el motor GH-002:** El motor interno de SecureCode (`securecode.adapters.github.get_gh002_evidence`) evalúa si la rama por defecto del repositorio tiene protección habilitada (`protection_enabled`). Actualmente, si SecureCode se evalúa a sí mismo, el control GH-002 resulta no conformante debido a la ausencia de branch protection en GitHub.

## 3. Requisitos de Gobernanza

La especificación GOV-001 define los siguientes requisitos obligatorios:

1. **REQ-GOV-01: Prohibición de Push Directo a `main`**  
   Toda modificación a `main` debe originarse mediante un Pull Request.
2. **REQ-GOV-02: Status Checks Obligatorios (Quality Gates)**  
   No se podrá fusionar ningún PR a `main` si alguno de los siguientes checks falla o no se ejecuta:
   - `test`
   - `docker-smoke-test`
3. **REQ-GOV-03: Rama Actualizada antes de Merge (Strict Status Checks)**  
   La rama del PR debe estar sincronizada con el commit más reciente de `main` antes de la integración (`strict: true`).
4. **REQ-GOV-04: Prohibición de Force Push**  
   Se bloquean completamente operaciones destructivas de historial (`git push --force`) sobre `main`.
5. **REQ-GOV-05: Prohibición de Eliminación de Rama**  
   Se impide el borrado remoto de `main`.
6. **REQ-GOV-06: Resolución de Conversaciones Obligatoria**  
   Todos los hilos de conversación y comentarios de revisión en el PR deben estar marcados como resueltos antes del merge.
7. **REQ-GOV-07: Prevención de Bloqueo a Mantenedor Individual**  
   En consideración a que el repositorio opera con un mantenedor principal individual:
   - Si se utiliza **Branch Protection clásica**, `enforce_admins` se mantendrá en `false` o no se exigirá `required_approving_review_count >= 1` obligatorio sin bypass, para evitar que el autor quede en bloqueo ("deadlock") permanente al no poder auto-aprobar sus propios PRs en GitHub.
   - Si se utilizan **GitHub Rulesets**, se configurará la regla `pull_request` con `required_approving_review_count: 0`, garantizando que todo cambio pase obligatoriamente por PR y checks de CI, pero permitiendo el merge por el mantenedor sin requerir aprobación externa.

## 4. Configuración Propuesta

### Opción Recomendada: Classic Branch Protection con Compatibilidad GH-002

Debido a que el adaptador de telemetría de SecureCode (`src/securecode/adapters/github.py:192`) consulta explícitamente el endpoint REST `/repos/{owner}/{repo}/branches/{branch}/protection`, la **Branch Protection clásica** asegura tanto la gobernanza real como el cumplimiento nativo de los controles evaluados por SecureCode.

#### Payload de Configuración (`PUT /repos/Medalcode/SecureCode/branches/main/protection`):
```json
{
  "required_status_checks": {
    "strict": true,
    "contexts": [
      "test",
      "docker-smoke-test"
    ]
  },
  "enforce_admins": false,
  "required_pull_request_reviews": null,
  "restrictions": null,
  "required_linear_history": false,
  "allow_force_pushes": false,
  "allow_deletions": false,
  "required_conversation_resolution": true
}
```

*Nota sobre `required_pull_request_reviews`:*
En Classic Branch Protection, activar `required_pull_request_reviews` obliga a un valor mínimo de `required_approving_review_count` de **1**. En un repositorio personal, GitHub prohíbe que el autor apruebe su propio PR. Con `enforce_admins: false`, el administrador puede fusionar el PR tras la aprobación de los checks; si se requiriera un segundo revisor constante (`josemorahj`), se puede activar `required_approving_review_count: 1`.

#### Alternativa Moderna: GitHub Rulesets (Regla de PR sin aprobación obligatoria)
Si el objetivo es forzar formalmente la interfaz de Pull Request sin permitir empuje directo ni requerir un segundo aprobador:
- Target: `~DEFAULT_BRANCH` (`main`).
- Reglas:
  - `deletion: true`
  - `non_fast_forward: true`
  - `required_status_checks`: checks `test` y `docker-smoke-test`, `strict_required_status_checks_policy: true`.
  - `pull_request`: `required_approving_review_count: 0`, `required_review_thread_resolution: true`.

## 5. Limitaciones del Plan GitHub y Viabilidad

| Característica | Repositorio Privado Free | Repositorio Público Free (Actual) |
| :--- | :--- | :--- |
| Classic Branch Protection | No disponible (requiere Team/Enterprise) | **Disponible y Totalmente Funcional** |
| Required Status Checks | No disponible en Free | **Disponible y Totalmente Funcional** |
| Repository Rulesets | Limitado en Free | **Disponible y Totalmente Funcional** |
| Restricción de Bypass por Rol | Requiere Enterprise | Disponible para administradores |

**Conclusión de viabilidad:** Dado que `Medalcode/SecureCode` es un repositorio **público**, no existe ninguna restricción de licencia ni costo económico para habilitar Branch Protection o Rulesets con checks requeridos (`test` y `docker-smoke-test`).

## 6. Riesgos y Mitigaciones

| Riesgo | Impacto | Mitigación |
| :--- | :--- | :--- |
| **Bloqueo de desarrollo individual (Deadlock)** | Crítico: Si se exige 1 aprobación externa en un repo individual y `enforce_admins: true`, el mantenedor no puede fusionar cambios propios si el colaborador no está disponible. | Configurar `enforce_admins: false` en Branch Protection, o fijar `required_approving_review_count: 0` en Rulesets. |
| **Cambio de nombre de Job en CI** | Alto: Si se renombra `test` en `tests.yml`, los PRs no podrán fusionarse al quedar en espera permanente. | Monitorear cambios en nombres de Jobs en los workflows de CI antes de modificarlos. |
| **Falso negativo en GH-002** | Medio: Si se usan sólo Rulesets sin Branch Protection clásica, `GET /branches/main/protection` devuelve 404, marcando GH-002 como no conforme. | Aplicar Branch Protection clásica en la rama `main`. |
| **Inestabilidad por force push accidental** | Crítico: Pérdida de commits validados. | Regla explícita `allow_force_pushes: false`. |

---

## 7. Criterios de Aceptación

1. `GET /repos/Medalcode/SecureCode/branches/main` reporta `"protected": true`.
2. `GET /repos/Medalcode/SecureCode/branches/main/protection/required_status_checks` lista exactamente:
   - `contexts`: `["test", "docker-smoke-test"]`
   - `strict`: `true`
3. Intentar `git push origin main` directamente (sin PR) es rechazado por GitHub.
4. Intentar `git push --force origin main` es rechazado por GitHub.
5. Un PR con checks `test` o `docker-smoke-test` en estado pendiente o fallido tiene el botón de merge bloqueado.
6. El motor SecureCode al auditar `main` reporta el control GH-002 como `PASS` (`protection_enabled: true`).

## 8. Procedimiento de Reversión

En caso de requerirse la desactivación inmediata de las protecciones de emergencia:

### Mediante GitHub CLI:
```bash
# Eliminar protección clásica de la rama main
gh api -X DELETE repos/Medalcode/SecureCode/branches/main/protection

# En caso de haber configurado Rulesets:
# Listar id del ruleset
RULESET_ID=$(gh api repos/Medalcode/SecureCode/rulesets --jq '.[0].id')
# Eliminar el ruleset
gh api -X DELETE repos/Medalcode/SecureCode/rulesets/$RULESET_ID
```

### Verificación de Reversión:
```bash
gh api repos/Medalcode/SecureCode/branches/main --jq '.protected'
# Salida esperada: false
```
