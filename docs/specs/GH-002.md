# GH-002: Default Branch Protection Enabled

## Purpose
To ensure that all repositories have branch protection enabled on their default branch, preventing unreviewed or unauthorized code from being merged directly into production.

## Control Objective
The repository's default branch must have branch protection configured.

## Required Evidence
The `GH002Evidence` model captures:
- `default_branch` (str): The name of the default branch.
- `protection_enabled` (Optional[bool]): Whether branch protection is active for that branch.

## Deterministic Evaluation Rule
- **PASS**: `protection_enabled` is explicitly `True`.
- **FAIL**: `protection_enabled` is explicitly `False`.
- **UNKNOWN**: `protection_enabled` is `None` (evidence is missing or cannot be trusted).

## GitHub Endpoints
The adapter uses a sequential flow to reliably distinguish between a missing repository/branch and an unprotected branch:
1. `GET /repos/{owner}/{repo}` to identify the `default_branch`.
   - `404/403/401` -> UNKNOWN (Repository inaccessible or missing).
2. `GET /repos/{owner}/{repo}/branches/{default_branch}` to verify the branch actually exists.
   - `404/403/401` -> UNKNOWN (Branch missing or inaccessible).
3. `GET /repos/{owner}/{repo}/branches/{default_branch}/protection` to determine protection.
   - `200 OK` -> `protection_enabled = True` (PASS).
   - `404 Not Found` -> `protection_enabled = False` (FAIL). Since step 2 confirmed the branch exists, a 404 here definitively means protection is not configured.
   - `401/403` -> `protection_enabled = None` (UNKNOWN). Insufficient API scope.

## Limitations
- GitHub uses `404` ambiguously. We mitigate this by checking branch existence *before* checking protection, ensuring a 404 on the protection endpoint unambiguously means "unprotected".
- The `protection` endpoint strictly requires authentication (`GITHUB_TOKEN`), even for public repositories.
